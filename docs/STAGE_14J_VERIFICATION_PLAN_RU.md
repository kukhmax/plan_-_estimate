## 2. Подэтапы

### 14J.1 — PostgreSQL 16: миграции и существующие opt-in модули
- Одноразовый кластер, `alembic upgrade head` с пустой базы; `downgrade` до `0030` и повторный `upgrade` (цепочка `0031`–`0036` обратима на PostgreSQL); прогон существующих PostgreSQL-модулей (14C.6B, 14D.2A) и сторожа `pg_scratch_guard`.
- PASS: все существующие PG-тесты проходят, миграции вверх / вниз / вверх без ошибок, `alembic heads` = `0036_photo_annotation_outline`.

### 14J.2 — новые PostgreSQL-доказательства для 14F–14I (новый модуль `tests/test_stage14j_postgres.py`, opt-in)
- Ограничения: CHECK координат меток (x, y за 0…1, `position < 0`), CHECK контекстов (INSPECTION / FINDING / WORK с неверными колонками), частичные уникальные индексы активных вложений.
- Гонки: 12 параллельных создателей метки при 9 существующих → ровно одна проходит, остальные `PHOTO_ANNOTATION_LIMIT_REACHED`, итог 10; параллельные правки контура одной метки не портят JSON; повтор раундами (`PG_RACE_ROUNDS`).
- Данные: `GET /photos/counts` и `PhotoReportReadModel` на сотнях фото — тот же результат, что на SQLite для того же набора, время и число запросов зафиксированы (не растёт с числом фото).
- PASS: все новые PG-тесты проходят на PostgreSQL 16 и пропускаются без `TEST_PG_URL`.

### 14J.3 — состязательная матрица владельцев по новым маршрутам (SQLite, обычный набор)
- Расширить матрицу 14C.6B: маршруты меток (список / создание / правка / удаление), `GET /photos/counts`, фото INSPECTION / FINDING / WORK (загрузка, список, детали) — чужой владелец, чужой проект, архивное вложение / актив, выдуманные id → фиксированные коды и конверты, без ключей хранилища, sha256 и данных другого владельца.
- Защита от «забытого» маршрута: тест перечисляет все маршруты приложения с «photo» в пути и требует, чтобы каждый был либо в матрице, либо в явном списке исключений с причиной; без токена — 401.
- PASS: новые тесты проходят; мутация (убрать проверку владельца в одном маршруте) ломает тест.
