# V2-7a — свои документы в базе знаний

Ветка `ver-2`. Промежуточный этап между V2-7 и V2-8 по просьбе владельца 2026-10-25 (после приёмки V2-7). **Миграция 0071** (две НОВЫЕ таблицы; существующие не меняются; обратима — но откат удаляет документы владельца). Решения владельца: файлы хранятся **в базе данных**; разрешены **PDF и фото страниц (JPG, PNG)**; в окне, кроме названия, ссылки, файла и текста: **вид документа, метки, дата документа («актуально на»), заметка «когда применять»**.

## Что входит

* **Раздел «Moje dokumenty»** на экране базы знаний, под полем поиска: заголовок со счётчиком, кнопка «Dodaj dokument» (на всю ширину, ≥ 48 px), список (название, вид, значки 📎 файл / 🔗 ссылка / 📝 текст, метки, две строки текста); первые пять, остальные по кнопке. Поле поиска базы знаний фильтрует и свои документы (сервер ищет по началам слов, без учёта регистра и диакритики: название → метки → «когда применять» → имя файла → текст).
* **Окно «Dodaj dokument» / «Zmiana dokumentu»** (нижний лист, как «5 cen na start»): название (обязательно), вид (Przepisy / Norma / Karta techniczna producenta / Wzór pisma lub umowy / Inne), ссылка http(s), файл (PDF, JPG или PNG ≤ 10 МБ: «выбрать / заменить / убрать»), текст (до 100 000 знаков), дата документа, «когда применять» (до 1000 знаков), метки через запятую (до 10, по 30 знаков). Нужно что-то одно из трёх: текст, ссылка или файл.
* **Карточка документа:** вид, метки, дата, «когда применять», ссылка («Otwórz link» — через Telegram `openLink`), файл (картинка открывается внутри приложения; PDF — в браузере открывается в новой вкладке, а **в Telegram отправляется в чат с ботом** кнопкой «Wyślij plik do czatu»), текст, «Edytuj», «Usuń…» (удаление навсегда после подтверждения).
* **Хранение:** таблица `knowledge_documents` (поля и метки) и `knowledge_document_files` (байты файла; список их не читает). Файл проверяется по первым байтам (не по имени): `%PDF-`, JPEG, PNG; имя очищается; тип в ответе фиксирован, `nosniff` и `sandbox`. Пределы: 10 МБ на файл, 100 документов и 300 МБ файлов на владельца. Документы принадлежат владельцу (`owner_id`); чужой документ — 404.
* **API** (`/api/knowledge/documents`): `GET` список (`q`, `kind`), `POST` (multipart-форма: поля + необязательный `file`), `GET/PUT/DELETE /{id}`, `GET /{id}/file`, `POST /{id}/send`. Форма читается вручную под предел размера (как загрузка фото): владелец известен до первого байта файла, тело не может превысить 10,7 МБ при любом Content-Length.

## Что остаётся прежним

* Утверждённая база знаний (законы, нормы, ситуации) остаётся только для чтения и одинаковой для всех; свои документы **не смешиваются** с ней и **не попадают** в PDF для клиента, договоры и протоколы.
* Документы хранятся открытым текстом (как прайс): это справочные материалы владельца, а не данные клиентов; в них не следует вставлять персональные данные клиентов. Файлы входят в обычный бэкап A9 (размер бэкапа растёт на размер файлов).
* Поиск **внутри PDF** не делается (нужна распознающая библиотека; без новых зависимостей): ищется по названию, меткам, «когда применять», имени файла и тексту — поэтому важное из PDF стоит вставить текстом.
