# V2-14a — «Перенести» ответы мастера в «Punkty i trasy» и в материалы помещения

Запрос владельца (2026-11-04, после приёмки V2-14): «отправка ссылки для мастера работает, продолжаем с V2-14a». Продолжение `docs/V2_14_PLAN_RU.md`.

## 1. Что делает шаг

В карточке мастера («Linki dla majstrów» → «Elektryk» / «Hydraulik») появляется кнопка **«Przenieś do pomieszczeń»**. Она открывает **предпросмотр** (ничего не записывается), где видно:

* для каких типовых позиций какая позиция вашего прайса будет подставлена (выбор из списка; по умолчанию подбирается по названию типовой позиции «Punkt elektryczny…», «Punkt wodny», «Trasa rurowa»…);
* по помещениям: что будет **добавлено**, что **изменится** (было → станет), что **будет убрано** (мастер поставил 0 или стёр);
* что получится в **материалах** помещения (расчёт «Elektryka» / «Hydraulika» из тех же чисел).

Кнопка **«Przenieś»** записывает. Повтор **не дублирует**: переносимые строки помечены источником, повторный перенос обновляет именно их.

## 2. Решения (можно отменить)

* **Только по вашей кнопке.** Мастер ничего сам в помещения не пишет.
* **Свои строки не трогаются.** Переносимые строки (и расчёт материалов) помечены `source = 'TRADE_LINK'`; то, что вы ввели вручную, перенос не меняет и не удаляет, даже если там та же позиция прайса.
* **«Punkty i trasy»:** одна строка на помещение и позицию прайса; если две типовые позиции ведут в одну позицию прайса (розетки и выключатели → «Punkt elektryczny - gniazdko / włącznik»), числа **суммируются**. Примечания мастера склеиваются в примечание строки. Количество 0 или пусто = строки нет (если она была перенесена раньше, она **убирается**). «Obwody» и «Wyjścia z rozdzielacza» в «Punkty i trasy» не идут (у них нет позиции прайса) — только в материалы.
* **Материалы:** один расчёт пакета «Elektryka» / «Hydraulika» на помещение с числами мастера (`sockets`, `switches`, `lights`, `circuits`, `route_m` / `water_points`, `drain_points`, `manifold_outlets`, `pipe_m`); без названия. Все числа 0 — перенесённый расчёт убирается.
* **Свои позиции мастера** (с именем) в прайс не превращаются: в предпросмотре они показаны списком «не переносятся» (чтобы вы добавили их вручную при необходимости).
* **Смета не меняется.** Строки, уже добавленные в смету, остаются как были (смета хранит снимок); новые строки попадут в смету обычной кнопкой «Dodaj punkty i trasy z pomieszczeń».
* **Профессии V2-13 не мешают:** перенос работает независимо от галочек (мастера вы позвали сами).

## 3. Данные (миграция 0086; существующие строки не меняются)

* `room_points.source` и `material_calcs.source`: необязательная короткая строка (`NULL` = ввели вы; `TRADE_LINK` = перенесено из ответа мастера). Откат миграции убирает колонки (строки остаются как ваши).

## 4. API (владелец)

* `POST /api/projects/{id}/trade-links/{trade}/transfer/preview` — тело `{mapping: {ключ: id позиции прайса | null}}` (ключ не указан — берётся подбор по умолчанию); ответ: позиции с кандидатами и подбором, помещения со строками (статус NEW / CHANGE / SAME / REMOVE), расчёт материалов (NEW / CHANGE / SAME / REMOVE), число своих позиций мастера, которые не переносятся.
* `POST /api/projects/{id}/trade-links/{trade}/transfer` — тело `{mapping, points: bool, materials: bool}`; записывает всё одной транзакцией, возвращает счётчики. Ошибки: `TRANSFER_NOTHING` (нечего переносить), `TRANSFER_ITEM_INVALID` (чужая / архивная / не шт.-мп позиция).

## 5. Проверка

* backend: правила подбора и суммирования, предпросмотр = то, что запишет перенос, повтор не дублирует, 0 убирает свою строку и не трогает ручную, чужой владелец / чужой объект, миграция 0086 (SQLite и PG16);
* frontend: кнопка, предпросмотр, выбор позиции, перенос, повтор, 4 языка; мобильная матрица 320 / 390 / 419.
