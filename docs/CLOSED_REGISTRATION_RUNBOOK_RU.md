# Закрытая регистрация — runbook

Статус: **готово локально (2026-10-19), ветка `backlog-closed-registration`, не выложено.** Бэклог-пункт, **не этап дорожной карты**. Миграция `0065_access_control`, backend + frontend, без новых зависимостей.

## 1. Что это

До сих пор любой пользователь Telegram, открывший бота, сам получал учётную запись. Теперь приложение можно **закрыть**: входят только аккаунты из списка доступа со статусом `ACTIVE`.

| Статус | Значение |
|---|---|
| `PENDING` («Oczekujące») | Открыл бота при закрытой регистрации; ждёт вашего решения. Записываются только его публичные данные Telegram (id, ник, имя) |
| `ACTIVE` («Aktywne») | Может работать |
| `BLOCKED` («Zablokowane») | Отказано при любом режиме регистрации |

* **Администратор** — строка списка с признаком «администратор». Он входит всегда и **не может быть заблокирован или удалён с экрана**; менять его можно только командой на сервере.
* **Проверка на каждом запросе**, а не только при входе: блокировка действует сразу, не дожидаясь окончания семидневного токена. Проверка идёт **в том же SQL-запросе, который читает пользователя** (дополнительных запросов нет).
* Отказанный человек видит «Brak dostępu» и контакт, который вы вписали на экране «Dostęp». У него **не создаётся** ни пользователь, ни ключ шифрования, ни токен.
* Защита от потока заявок: при закрытой регистрации хранится не больше 200 ожидающих; сверх этого человеку отказывают без записи.
* Когда регистрация **открыта**, вошедший пользователь записывается в список как `ACTIVE` — чтобы последующее закрытие не выгнало тех, кто уже работает.

## 2. Что делает миграция 0065

Создаёт `access_entries` и `access_settings`; **ничего в существующих таблицах не меняет**. Все нынешние пользователи становятся `ACTIVE`; **самый ранний по `created_at` (первый вошедший — вы) становится администратором**; настройка `closed` = `1`. Откат миграции удаляет обе таблицы; прежний образ работает и на новой схеме.

`docs/CLOSED_REGISTRATION_DEPLOY_RU.sh` (фраза `ВЫКЛАДКА ДА`): G0 только чтение (база на `0064`, бэкап не старше суток, образы/зависимости/compose без изменений, ровно одна новая миграция, список пользователей и кто станет администратором), G1 сборка с тегами `pre-access`, ворота B, G2 backend (миграция в логе, `0065`, строгое чтение, администратор один и он самый ранний, все нынешние пользователи допущены, чужой аккаунт отклоняется — на настоящей базе, только чтение), G3 frontend, G4 кнопка меню Telegram. Повторный запуск безопасен.

**Бэкап до выкладки** делается из `main` (пока она на `0064`): `BACKUP_BRANCH=main BACKUP_HEAD=0064_encrypted_payments bash ~/backup_a9.sh`.

## 4. Если что-то пошло не так

| Ситуация | Что делать |
|---|---|
| Пункта «Dostęp» нет в меню | Администратором стал не тот аккаунт: `docker exec plan_estimate_backend python -m app.cli.access set-admin --telegram-id <id>` |
| Не могу войти сам | `docker exec plan_estimate_backend python -m app.cli.access open` (регистрация открыта; вы входите как обычно), затем разобраться; вернуть: `... close` |
| Узнать состояние | `docker exec plan_estimate_backend python -m app.cli.access status` (только числа) |
| Откатить выкладку | Образы `pre-access` (команда печатается скриптом); таблицы остаются, прежнему коду они не мешают |
