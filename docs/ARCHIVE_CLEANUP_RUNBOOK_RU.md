## 4. Откат — ПОРЯДОК ВАЖЕН

**Важная находка при подготовке (проверена на PostgreSQL):** старый образ backend **не запустится** на базе с применёнными миграциями — входной скрипт делает `alembic upgrade head`, а старый код не знает версию `0057` (`Can't locate revision`). Поэтому откат образа без отката миграций **не работает** (утверждение «откат образа безопасен без отката миграции» в runbook Stage 18 было неверным; тогда до отката дело не дошло). Рабочий порядок (скрипт печатает его при любом отказе после ворот M):

1. сначала откатить миграции **новым** кодом (без потерь): `docker compose --env-file .env.production -p plan-estimate -f docker-compose.prod.yml run --rm --no-deps --entrypoint alembic backend downgrade 0055_project_notes`;
2. вернуть оба образа: `docker tag plan-estimate-backend:pre-ac plan-estimate-backend:latest && docker tag plan-estimate-frontend:pre-ac plan-estimate-frontend:latest`;
3. `docker compose --env-file .env.production -p plan-estimate -f docker-compose.prod.yml up -d --no-deps --no-build backend frontend`.

**Граница отката:** откат `0057` отказывается, пока в реестре есть записи — то есть **пока не было настоящего удаления фото**. После первого настоящего удаления назад пути нет, только вперёд (исправлять новым выпуском). Поэтому настоящее удаление — отдельный шаг после приёмки (раздел 5, п. 8).
Новый frontend со старым backend не работает (новые маршруты), поэтому откатываются оба образа сразу.
