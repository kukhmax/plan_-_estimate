1. **Проверьте, что VM на `main` и чисто:** `cd ~/apps/plan_-_estimate && git branch --show-current && git status --short` (ожидается `main`, пусто).

   ```
   cd ~/apps/plan_-_estimate && git fetch -q origin main && git show origin/main:docs/STAGE_18_BACKUP_A9_RU.sh > ~/backup_a9.sh && BACKUP_BRANCH=main BACKUP_HEAD=0055_project_notes bash ~/backup_a9.sh
   ```
   Ожидается `A9 PASS`. После этого **закройте эту SSH-сессию** (в оболочке остаются переменные бэкапа).
3. **Выкладка** (новая сессия; скрипт сам берёт файл из origin, VM не меняется до проверок):
   ```
   cd ~/apps/plan_-_estimate && git fetch -q origin backlog-archive-cleanup && git show origin/backlog-archive-cleanup:docs/ARCHIVE_CLEANUP_DEPLOY_RU.sh > ~/deploy_ac.sh && bash ~/deploy_ac.sh
   ```
   Ход: G0 проверки (только чтение) → G1 сборка (старый production работает) → **ворота M**: фраза **`МИГРАЦИИ 0056 0057 ДА`** → G2 backend и миграции → G3 frontend → G4 кнопка Telegram с новым `?v=`. Любой отказ останавливает всё и печатает порядок отката. Присылайте весь вывод.
4. **Телефон** (раздел 5).
5. **Бэкап под новую голову** (образы бэкапа теперь знают реестр удалений; без него следующий бэкап при голове `0057` откажется работать): новая сессия,
   ```
   cd ~/apps/plan_-_estimate && BACKUP_BRANCH=backlog-archive-cleanup BACKUP_HEAD=0057_purge_ledger bash ~/backup_a9.sh
   ```
   (скрипт `~/backup_a9.sh` уже лежит с шага 2). Потом закройте сессию.
6. **Приёмка и слияние в `main`:** «принимаем» — моя запись в журнале; слияние `backlog-archive-cleanup` → `main` и переключение VM на `main` — только по вашему отдельному «да».

## 4. Откат — ПОРЯДОК ВАЖЕН

**Важная находка при подготовке (проверена на PostgreSQL):** старый образ backend **не запустится** на базе с применёнными миграциями — входной скрипт делает `alembic upgrade head`, а старый код не знает версию `0057` (`Can't locate revision`). Поэтому откат образа без отката миграций **не работает** (утверждение «откат образа безопасен без отката миграции» в runbook Stage 18 было неверным; тогда до отката дело не дошло). Рабочий порядок (скрипт печатает его при любом отказе после ворот M):

1. сначала откатить миграции **новым** кодом (без потерь): `docker compose --env-file .env.production -p plan-estimate -f docker-compose.prod.yml run --rm --no-deps --entrypoint alembic backend downgrade 0055_project_notes`;
2. вернуть оба образа: `docker tag plan-estimate-backend:pre-ac plan-estimate-backend:latest && docker tag plan-estimate-frontend:pre-ac plan-estimate-frontend:latest`;
3. `docker compose --env-file .env.production -p plan-estimate -f docker-compose.prod.yml up -d --no-deps --no-build backend frontend`.

**Граница отката:** откат `0057` отказывается, пока в реестре есть записи — то есть **пока не было настоящего удаления фото**. После первого настоящего удаления назад пути нет, только вперёд (исправлять новым выпуском). Поэтому настоящее удаление — отдельный шаг после приёмки (раздел 5, п. 8).
Новый frontend со старым backend не работает (новые маршруты), поэтому откатываются оба образа сразу.

## 5. Чек-лист на телефоне (полностью закройте Telegram, откройте Mini App по кнопке меню)

6. Календарь, объекты, помещения, фото — как раньше (регресс).
7. `/api/health` ok; число файлов в R2 (панель Cloudflare) не изменилось, кроме вашего тестового фото.
8. **Настоящее удаление тестового фото — только после приёмки и вашего отдельного «да»** (закрывает границу отката из раздела 4): фото → архив → «Kosz» → «Usuń na zawsze…» → подтвердить.
