# V2-1 — вход без Telegram (ветка `ver-2`, прод)

Статус: **в работе (2026-10-23)**, решения владельца: работаем **сразу в production из ветки `ver-2`, без отдельного стенда** (V2-0 отменён); каждый шаг с миграцией — выкладка со свежим бэкапом (A9) и воротами G0–G4; первый шаг — V2-1; вход по паролю на проде остаётся **выключенным флагом** до решения владельца и фазы M.

## Что строим

Мастер без Telegram заходит в приложение из обычного браузера по e-mail и паролю. Аккаунты создаёт владелец командой. Telegram-вход не меняется.

## Решения проекта (владелец может изменить до выкладки)

| Вопрос | Решение | Почему |
| --- | --- | --- |
| Где хранить пароль | новая таблица `user_credentials` (user_id, e-mail, хэш, счётчик ошибок, блокировка) | персональные данные Telegram-пользователей не трогаются; миграция 0067 — две новые вещи, существующие таблицы не меняются |
| Идентификатор пользователя без Telegram | `users.telegram_user_id` остаётся `NOT NULL UNIQUE`; веб-аккаунт получает **отрицательное** число (-1, -2, …) | список доступа («Dostęp»), блокировка, администратор и все проверки работают без изменений; настоящие id Telegram всегда положительные, коллизий нет |
| Хэш пароля | `scrypt` из стандартной библиотеки (N=2^15, r=8, p=1, соль 16 байт, сравнение `hmac.compare_digest`) | **без новой зависимости**: прежние скрипты выкладки отказывают при изменении зависимостей |
| Пароль | не короче 12 знаков; хранится только хэш; не пишется в логи | |
| Защита от подбора | 5 неверных попыток подряд → блокировка аккаунта на 15 минут; одинаковый ответ для «нет такого e-mail» и «неверный пароль» (с тем же временем: хэш считается и для несуществующего) | |
| Флаг | `AUTH_PASSWORD_ENABLED` (по умолчанию `false`); при `false` вход отвечает `PASSWORD_LOGIN_DISABLED` и экран входа не показывается | прод остаётся как сейчас, пока владелец не включит |
| Создание аккаунтов | `python -m app.cli.users create --email … --name …` (пароль генерируется и печатается один раз, либо `--password-stdin`), `set-password`, `list` (без паролей) | |
| Список доступа | `create` записывает аккаунт в список доступа как ACTIVE: блокировка на экране «Dostęp» действует и на веб-аккаунт | |
| Что НЕ работает у веб-аккаунта в V2-1 | доставка PDF в чат Telegram и напоминания бота (их заменят скачивание PDF — V2-4, ссылка клиенту — V2-8); система не пытается слать в чат с отрицательным id | честно сказано в экране/журнале |

## Файлы

Backend: `alembic/versions/0067_password_login.py`, `models/user_credential.py`, `domain/services/password_login_service.py` (хэш, проверка, блокировка), `api/v1/endpoints/auth.py` (+`POST /api/auth/password`, `GET /api/auth/config`), `schemas/auth.py`, `core/config.py` (+флаг), `cli/users.py`, `domain/services/calendar_dispatcher.py` (пропуск отрицательных id), `domain/documents/issuer.py` / `delivery.py` (понятный отказ).
Frontend: `components/LoginScreen.tsx`, `api/auth.ts`, `hooks/useAuth.ts`, тексты `pl.json` / `ru.json`.

## Тесты и критерии PASS

* Хэш: проверка верного и неверного пароля, разные соли, параметры в строке хэша.
* Вход: верный → токен, тот же формат ответа; неверный пароль и неизвестный e-mail → один и тот же ответ; 5 ошибок → блокировка, верный пароль в блокировке отказан, после срока вход возможен; флаг выключен → отказ; заблокированный в списке доступа → отказ; e-mail без учёта регистра.
* Токен веб-аккаунта работает во всех маршрутах (`/api/me`, клиенты…); данные двух аккаунтов не пересекаются.
* CLI: `create` (отрицательный id, запись в список доступа, пароль не в логах), повтор e-mail отказ, `set-password`, `list`.
* Telegram-вход не изменился (все прежние тесты зелёные); напоминания и PDF веб-аккаунту не уходят в Telegram.
* PostgreSQL 16: миграция вверх / вниз / вверх на базе с данными; вход и CLI.
* Frontend: экран входа (поля 44 px, ошибки PL/RU, блокировка, показать пароль), при `password_login=false` прежнее сообщение; Telegram-вход без изменений; живое приложение на 320 / 390 / 412 px, PL и RU, светлая и тёмная.
* Скрипт выкладки `docs/V2_1_DEPLOY_RU.sh` (миграция 0067, backend + frontend, бэкап не старше суток, флаг остаётся `false`).

## Не входит

Регистрация самим мастером, «забыл пароль» по e-mail (нет почтового сервиса), привязка веб-аккаунта к Telegram, вход через Google/Apple — отдельные пункты фазы M.
