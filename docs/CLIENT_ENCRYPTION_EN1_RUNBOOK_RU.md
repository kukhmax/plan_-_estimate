# EN-1: страница-тест «Test zabezpieczeń» — runbook

Статус: **подготовлено 2026-10-18, на production не применялось.** Ветка `backlog-client-encryption`, скрипт `docs/CLIENT_ENCRYPTION_EN1_DEPLOY_RU.sh` (проверен на заглушках `docker` / `curl` поверх настоящего git). План: `docs/CLIENT_DATA_ENCRYPTION_PLAN_RU.md` (раздел 5 и шаг EN-1).

## 1. Что это и зачем

Страница спрашивает **ваш телефон**, а не документацию: что Telegram на нём реально умеет хранить и как быстро он считает. Из ответа проектируется V2 (ключ владельца): куда класть ключ, нужна ли биометрия, какие параметры KDF (PBKDF2 / Argon2) терпимы по времени, что переживает переустановку Telegram и смену телефона.

**Данных клиентов страница не трогает и ничего не отправляет на сервер.** Она пишет в хранилища Telegram короткие пробные значения `en1_*` и сразу удаляет их; единственное, что остаётся, — «метка» (дата и время), и только если вы нажмёте «Zapisz znacznik».

## 2. Что приходит и как выложить

Только frontend (меню получает последний пункт «Test zabezpieczeń»), плюс одна новая зависимость `hash-wasm` 4.12.0 (Argon2 в WebAssembly; отдельный кусок сборки, который грузится только на этой странице). **Backend, база, календарь не меняются, миграций нет**; контейнер backend не пересоздаётся (скрипт это проверяет).

Выкладка (новая SSH-сессия; после того как я запушу ветку по вашему «пуш»):
```
cd ~/apps/plan_-_estimate && git fetch -q origin backlog-client-encryption && git show origin/backlog-client-encryption:docs/CLIENT_ENCRYPTION_EN1_DEPLOY_RU.sh > ~/deploy_en1.sh && bash ~/deploy_en1.sh
```
G0 (проверки; в релизе только `frontend/src`, `package.json` с **ровно одной** новой строкой `hash-wasm`, запись в `package-lock.json`, docs; backend, Docker, compose, Caddy не изменены) → G1 (сборка frontend, старая версия работает) → **ворота B: `ВЫКЛАДКА ДА`** → G2 (backend тот же контейнер, healthy, база на `0061`, данные те же) → G3 (frontend: маркеры страницы, кусок Argon2 отдаётся) → G4 (кнопка Telegram). Откат: образ `pre-en1` (скрипт печатает команду).

## 3. Что сделать на телефоне (5–10 минут)

1. Полностью закройте Telegram, откройте Mini App по кнопке меню. Меню → последний пункт **«Test zabezpieczeń»**.
2. **«Uruchom testy»** — девять проверок идут по очереди (Argon2 и PBKDF2 могут занять несколько секунд). Если какая-то висит дольше 8 секунд, она станет «brak odpowiedzi»: это тоже результат.
3. **Биометрия:** «Poproś o dostęp do biometrii» → телефон задаст свой вопрос (разрешите), затем «Sprawdź odcisk / twarz» (приложите палец или лицо). Если биометрии на телефоне нет, будет «brak».
4. **Метки** (для проверки «что переживёт переустановку»): для **каждого** из трёх хранилищ нажмите «Zapisz znacznik», потом «Odczytaj znacznik» — должно вернуться то же время.
5. **«Kopiuj raport»** → вставьте в чат со мной (если копирование не сработало, выделите текст в поле «Raport do wysłania» и скопируйте вручную; можно и скриншот).

**Затем (по возможности, это самое ценное для V2):** не стирая меток, **переустановите Telegram** (или откройте страницу на другом телефоне с тем же аккаунтом) → снова «Test zabezpieczeń» → у каждого хранилища «Odczytaj znacznik». Пришлите, какие хранилища метку сохранили. Потом «Usuń znacznik» у каждого, чтобы ничего не оставалось.

## 4. Как читать результат (для меня)

| Проверка | Что решает |
|---|---|
| Telegram и телефон | версия Bot API, какие хранилища есть |
| AES-256-GCM | работает ли шифрование в браузере телефона (V1 его делает на сервере, V2 — нужен в Mini App) |
| PBKDF2 / Argon2id — скорость | допустимые параметры KDF для фразы восстановления (цель: до ~1 секунды на телефоне) |
| CloudStorage и размер значения | куда класть копию ключа, завёрнутую парольной фразой (нужно несколько сотен символов) |
| SecureStorage | хранить ли ключ владельца на устройстве защищённо |
| DeviceStorage | запасной вариант без защиты |
| Биометрия | разблокировать ключ отпечатком или лицом |
| Метки | что переживёт переустановку и смену телефона |

Если нет `SecureStorage` и нет биометрии, V2 строится на `CloudStorage` с парольной фразой и бумажной фразой восстановления (как в плане, раздел 5); если нет и `CloudStorage`, остаётся только бумажная фраза. Решение — на воротах EN-4, не сейчас.

## 5. Откат

Только frontend: `docker tag plan-estimate-frontend:pre-en1 plan-estimate-frontend:latest && docker compose --env-file .env.production -p plan-estimate -f docker-compose.prod.yml up -d --no-deps --no-build frontend` (скрипт печатает команду при любом отказе). Пробные значения `en1_*` страница сама удаляет; метки — кнопкой «Usuń znacznik».
