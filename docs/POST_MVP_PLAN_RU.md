Статус: **черновик для владельца (2026-10-19)**. Ни один шаг не начинается без явного «да» владельца.
Основа: анализ продукта, рынка и монетизации от 2026-10-19 (отдельный документ) и скриншоты владельца.

> **Как этот план соотносится с дорожной картой.** Канонические Stage 0–20 завершены и не меняются
> (`CLAUDE.md`, ROADMAP IMMUTABILITY). Всё ниже — отдельные **треки бэклога** со своими префиксами,
> как уже сделано с `EN-*` и `AC-*`: `U-*` (удобство), `V2-*` (версия 2), `R-*` (выпуск в Mini App),
> `M-*` (монетизация). Если владелец захочет сделать их новыми стадиями дорожной карты, это отдельное решение.


> **Решение владельца 2026-10-23 (меняет разделы 0, 2.1, 3):** отдельного стенда `v2.plan-estimate.pl` **не будет**. Фаза V2 ведётся **в ветке `ver-2`, а VM следует за ней** (прод). Каждый шаг с миграцией выкладывается на прод так же, как раньше: бэкап A9 не старше суток, ворота G0–G4, фраза `ВЫКЛАДКА ДА`, миграции обратимы, сверка данных до и после. Шаг V2-0 (стенд) отменён; фаза R (репетиция на копии) заменяется этими правилами. Вход по паролю остаётся **выключенным флагом** до решения владельца. `main` обновляется слиянием `ver-2` → `main` по отдельному «да». Порядок шагов не меняется; начинаем с V2-1 (`docs/V2_1_PLAN_RU.md`).

## 0. Порядок и ворота

```text
Фаза U  ── удобство MVP на проде (без миграций) ──► ворота U: владелец тестирует на объекте 1–2 недели
   │
Фаза V2 ── версия 2 локально и на стенде v2.plan-estimate.pl (вход без Telegram, свои данные)
   │       ──► ворота V2: 3–5 знакомых мастеров прошли «клиент → смета → ссылка клиенту» на стенде
   │
Фаза R  ── репетиция миграции на копии прода → выпуск V2 в Mini App ──► ворота R: прод на V2, данные равны
   │
Фаза M  ── юридическая база → тарифы → Stars и оплата на сайте → открытая регистрация и рост
```

| Фаза | Где работает | Миграции | Кто проверяет |
| --- | --- | --- | --- |
| U | прод (Mini App), как сейчас | **нет** | владелец на телефоне |
| V2 | локально + стенд `v2.plan-estimate.pl` | да, только на стенде | владелец + 3–5 мастеров |
| R | копия прода на стенде → прод | применяются к проду один раз | владелец |
| M | прод + сайт | да | владелец, бухгалтер, юрист |

### Общие правила для всех фаз

1. Процесс из `CLAUDE.md` не меняется: шаг → реализация → проверки → PASS/FAIL → коммит → «да» на push → «да» на выкладку → приёмка.
2. **Фаза U — без миграций базы.** Это позволяет выкладывать её на прод, пока на стенде растёт V2.
3. **Пока идёт V2, на `main` не появляются новые миграции.** Иначе цепочки Alembic `main` и `v2` разойдутся. Если прод срочно требует миграцию, её сначала вносят в `main`, затем сразу вливают `main` → `v2` и переставляют миграции V2 после неё.
4. Ветка `v2` создаётся от `main` после фазы U; изменения `main` вливаются в `v2` после каждой выкладки на прод.
5. На стенде **нет настоящих данных клиентов** (RODO): только демо-объекты и тестовые клиенты. Исключение — репетиция фазы R на копии прода, после которой копия удаляется.

## 2. Фаза V2 — версия 2 на отдельном стенде

### 2.1. Стенд

Подробная настройка: **`docs/V2_STAGING_SETUP_RU.md`**. Коротко:

* Адрес — **поддомен `v2.plan-estimate.pl`, а не путь `plan-estimate.pl/ver-2`.** Путь опасен: на одном
  адресе у прода и стенда общий `localStorage` и IndexedDB, а там лежит офлайн-кэш и очередь изменений прода
  (Stage 19). Версия 2 с изменённой схемой могла бы прочитать или отправить чужую очередь. Кроме того, путь
  требует переделать `/api`, базу сборки Vite и маршруты Caddy. Поддомен — отдельный origin, всё изолировано.
* На той же VM — **отдельный проект Docker Compose** `pe-v2`: своя PostgreSQL (свой том), свой backend,
  свой frontend, свой `DATA_KEK`, свой префикс или бакет R2. Общий только Caddy (новый блок сайта).
* Вход — **без Telegram**: email + пароль (аккаунты создаёт владелец командой) и, как внешний замок,
  Cloudflare Access (бесплатно до 50 пользователей, вход по коду на e-mail). Бот и напоминания на стенде выключены.
* Вход без Telegram — не временная заглушка: он же станет **веб-входом для польских мастеров** (у них
  Telegram мало распространён, см. анализ, раздел 7).

## 4. Фаза M — монетизация

Порядок важен: деньги нельзя принимать до юридической базы, а открывать регистрацию — до лимитов.

| Шаг | Что | Кто |
| --- | --- | --- |
| **M-0** | Юридическая база: форма бизнеса для продажи подписки (JDG / sp. z o.o.), учёт VAT по цифровым услугам, regulamin, polityka prywatności, реестр операций RODO, umowa powierzenia для подрядчиков | владелец + бухгалтер/юрист |
| **M-1** | Тарифы и права: таблица планов и подписок, проверка прав на сервере, лимиты Free (2 активных объекта, объём фото — на основе `photo_quota`), подпись «Сделано в Plan & Estimate» на PDF Free | разработка |
| **M-2** | Оплата Telegram Stars в Mini App: счёт в XTR, подписка на 30 дней, обработка `successful_payment` и продления, возвраты через `/paysupport` | разработка |
| **M-3** | Оплата на сайте: Stripe (BLIK с повторяющимися платежами + карта) или PayU, веб-хуки, автоматическая фактура через API inFakt / Fakturownia; тот же аккаунт | разработка |
| **M-4** | Приглашения по ссылке, открытая регистрация с лимитами, реферальная программа (месяц Pro за приглашённого, создавшего смету) | разработка |
| **M-5** | Решение по EN-4 (ключ владельца на телефоне), когда на сервере появятся чужие подрядчики | владелец |
| **M-6** | Рост: публичный сайт с шаблонами (protokół odbioru, umowa o remont), калькуляторы материалов, аналитика без персональных данных, метрика «первая смета клиенту за 7 дней» | разработка + владелец |
| **M-7** | Позже: «Команда» — субподрядчики на объекте (роли, доступ к своим помещениям) | после 100+ активных |

**Ворота M:** первые 10 платящих пользователей; доля перехода Free → Pro известна; только после этого — платная реклама.
