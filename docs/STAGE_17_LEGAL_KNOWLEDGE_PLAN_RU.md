## 1. Что такое Stage 17

Дорожная карта: «Polish Building Law, ITB conditions, PN-EN norms and a quick legal/technical situation lookup, served from the backend (never hardcoded in UI). Consumed by Stages 8, 15, 16».

**Входит:**
- **Каталог знаний** на сервере: нормативные источники (Prawo budowlane, Kodeks cywilny, ustawa o prawach konsumenta, RODO, нормы PN-EN, технические условия ITB) и **записи** — короткие карточки «что это, к чему относится, что из этого следует исполнителю», со ссылкой на источник и датой проверки.
- **Поиск**: по тексту (с учётом польских букв) и по фильтрам (вид, работа, основание, тема).
- **Поиск по ситуации** — пошаговый выбор («что случилось»): результат — что делать, на каком основании, что сказать клиенту (фразы Stage 8) и какой документ выдать (Stage 15–16).
- **Связи с тем, что уже есть**: риск → основание, фраза клиенту → основание, положение договора → основание, протокол → основание.

**Не входит:** искусственный интеллект и «чат с законом» (правила проекта: только детерминированные правила); юридические консультации и толкование; электронная подпись; календарь и напоминания (Stage 18); работа без сети (Stage 19; API делаем пригодным для кэширования, но кэша не пишем); редактирование базы знаний в самом приложении.

## 3. Принципы (из правил проекта и уроков Stage 16)

1. **Детерминированно.** Поиск и подбор по ситуации — по ключам, тегам, фильтрам и словарям; один и тот же запрос всегда даёт один и тот же ответ, с объяснимым порядком.
2. **Происхождение содержимого.** У каждой записи: источник (акт / номер нормы / документ ITB), точное место (статья, пункт), **дата проверки** («stan na dzień»), кто утвердил. Запись без утверждения — **DRAFT**: видна владельцу с пометкой, **не попадает в документы клиенту**.
3. **Не выдумывать и не копировать.** Закон — ссылка на опубликованный текст (ISAP) и краткое **собственное изложение**, утверждённое владельцем / юристом. У каждой записи — **краткое изложение ключевых моментов своими словами, а в конце ссылка на источник** (решение владельца по Q4, уточнено 2026-10-11). Нормы PN-EN платные и защищены авторским правом: их текст не копируем, только своё изложение ключевых моментов, обозначение, название, место и ссылка (то же для ITB). Цитаты длиннее нескольких слов — только при явном праве на них.
4. **Польский — основной язык права**; русский — **пояснение для исполнителя**, помеченное как пояснение, а не текст нормы.
5. **Никаких фиксированных текстов в React**; дисклеймер «это не юридическая консультация» и подпись «stan na dzień» приходят с сервера.
6. **Замороженное остаётся замороженным.** Выданные договор и протоколы — неизменяемые снимки; база знаний на них не влияет, новые связи работают только в интерфейсе и новых документах.

## 4. Предлагаемая архитектура

**Данные — каталоги в репозитории, без таблиц и без миграций** (как каталоги Stage 16): `backend/app/domain/knowledge/catalog/`:
- `sources.json` — реестр источников: код, вид (`STATUTE` / `NORM` / `ITB` / `OTHER`), название, обозначение (Dz.U. / PN-EN / ITB), ссылка на публикацию, дата проверки.
- `entries.json` — записи: `code`, `kind`, `source` + `locator` (art. 638 § 1; pkt 5.2), `title_pl`, `summary_pl` (изложение), `explanation_ru`, `applies_to` (работы, основания, стандарты качества), `tags`, `status` (`DRAFT` / `APPROVED`), `approved_by` / `approved_on`, `checked_on`, `review_notes`.
- `situations.json` — ситуации: `code`, вопрос и варианты ответов (дерево из закрытого словаря), результат: шаги (что делать), основания (коды записей), фразы клиенту (коды Stage 8), документы (виды Stage 15–16), предупреждения («нужен юрист»).
- `links.json` — связи: риск → записи, положение договора → записи, протокол → записи, фраза → записи.

**Загрузка и проверка при старте** (приложение не запускается на неверных данных): уникальность кодов; каждая ссылка (`source`, `entries`, `risk`, `clause`, `phrase`, `document kind`) существует; у `APPROVED` есть кто / когда / дата проверки; у `DRAFT` нет подписи утверждения; русский текст без польской «цитаты» в кавычках; длина полей ограничена.

**Поиск:** в памяти (каталог небольшой — сотни записей, Redis не нужен): нормализация (нижний регистр, польские и русские буквы без диакритики), разбиение на слова, **префиксное** совпадение; порядок результата: точный код → слова в названии → теги → текст изложения; при равенстве — по коду. Фильтры: вид, работа, основание, качество, источник, статус.

**API (только чтение, `/api/knowledge/…`, токен владельца):** `GET /sources`, `GET /entries` (фильтры, `q`, страница), `GET /entries/{code}`, `GET /situations`, `GET /situations/{code}` (+ шаг «ответ → следующий вопрос или результат»), `GET /links?risk=…&clause=…` (основания к месту), `GET /meta` (версия каталога, дата, дисклеймер). Ответы содержат версию каталога — пригодны для кэширования (Stage 19).

**Интерфейс (мобильный, 320–412 px):**
- пункт меню **«Baza wiedzy / База знаний»** (шестой в меню): строка поиска, «Найти по ситуации», список тем; карточка записи: изложение, источник и место, «stan na dzień», пометка DRAFT, пояснение на русском;
- **«Ситуация»**: по одному вопросу на экране с крупными кнопками, результат — карточки «Что делать», «Основание», «Что сказать клиенту», «Какой документ выдать» (кнопки в нужный экран объекта);
- **контекстные «Podstawa / Основание»** (подэтап 17E): у карточки риска, у фразы клиенту, у положения договора и протокола — раскрывающийся список записей.

## 7. Риски и критерий готовности

| Риск | Что делаем |
|---|---|
| Юридически неверное содержимое | Только утверждённое владельцем / юристом; DRAFT помечен и не уходит клиенту; у каждой записи источник, место и дата проверки |

| Устаревшие нормы | «stan na dzień» на каждой записи и в API; проверка дат в тестах (запись старше срока — предупреждение владельцу) |

| Объём | Шесть небольших подэтапов; первая партия — 15–30 записей, расширяется отдельно |
