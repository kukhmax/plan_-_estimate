# V2-9 — деньги: график платежей по этапам, часы и маржа объекта

Решения владельца (2026-10-27, после приёмки V2-8d): **свой список этапов**; **часы вручную + необязательная ставка в профиле**; **график виден вам на экране объекта и в PDF «Harmonogram płatności»** (не на странице клиента по ссылке); **напоминания о сроках через календарь**.

## Разбивка на шаги (одна принятая часть — один шаг)
* **V2-9** (этот шаг, **миграция 0075**): график этапов, привязка поступлений к этапам, часы, ставка, маржа, экран.
* **V2-9a**: PDF «Harmonogram płatności» (номер `HPL/…`, рабочая и нумерованная форма; миграция расширяет вид документа).
* **V2-9b**: напоминания о сроках этапов через календарь (за день и в день срока).

## Что уже есть и не меняется
«Faktury i zaliczki» (`project_payments`): фактуры, авансы, оплаты, расходы; договорная сумма (`project_finance`); сводка и «результат» (получено − расходы) считает сервер (`domain/rules/payment_totals.py`). V2-9 надстраивается над этим.

## 1. График платежей по этапам
Этап — строка вашего списка: **название** («Zaliczka», «Po gładziach», «Odbiór»), **доля в % или сумма** (одно из двух), **срок** (необязательно).
* Процент считается от договорной суммы: сумма этапа = договорная × % ÷ 100 (округление до копейки вверх от половины). Договорная сумма изменилась — суммы процентных этапов следуют за ней; этап с фиксированной суммой остаётся.
* **Сверка:** «Suma etapów» против договорной суммы: хватает / превышает на N zł (если сумма задана). Сверка — подсказка, не запрет.
* **Поступления по этапам:** аванс или оплата («Od klienta») получает необязательное поле «Etap». Получено по этапу = сумма привязанных поступлений (не в архиве). Статус этапа считает сервер: **PAID** (получено ≥ суммы), **PARTIAL**, **OVERDUE** (срок прошёл, не оплачен), **OPEN**.
* **Одно касание «Otrzymano»:** создаёт оплату на **остаток этапа** с сегодняшней датой, привязанную к этапу (и название берётся из этапа) — без формы; детали правятся потом.
* Порядок: по сроку (без срока — в конце), затем по порядку ввода. Этап удаляется (это план, не учёт): привязанные поступления остаются без этапа.
* Нужна связь с сервером (как у договорной суммы): график не ставится в офлайн-очередь (отложено).

## 2. Часы
Запись: **дата** (по умолчанию сегодня), **часы** (0,25–24, шаг 0,25 допускается любой до 2 знаков), **заметка** (необязательно). Сумма часов по объекту — на сервере. Запись можно править и удалять (это ваш рабочий журнал, не бухгалтерия). Ставка **zł/час** — необязательное поле профиля исполнителя.

## 3. Маржа объекта (считает сервер, `domain/rules/margin.py`)
* **База:** договорная сумма; если её нет — сумма принятой / итоговой сметы (как подсказка в «Faktury i zaliczki»), с пометкой, откуда база; нет ни того ни другого — маржа не считается.
* **Расходы:** сумма расходов (без архивных), как в сводке.
* **Работа:** часы × ставка (только если ставка задана).
* **Маржа = база − расходы − работа.** Без ставки: «маржа до оплаты труда» = база − расходы и **zł / час** = (база − расходы) ÷ часы (если часы > 0). Процент от базы.
* Суммы берутся так, как записаны (договорная — как введена): **без пересчёта НДС** (отложено, подпись под блоком это говорит).

## 4. Экран «Faktury i zaliczki»
Сводка получает блок «Marża» (база, расходы, работа, маржа, % и zł/час); вкладки: «Faktury», «Od klienta», «Materiały» (как были) + **«Etapy»**, **«Godziny»**. Всё — вертикально, кнопки на всю ширину, ≥ 44 px, `inputMode="decimal"`. В форме аванса / оплаты — выбор этапа под «Opcje». В профиле исполнителя — поле «Stawka za godzinę».

## 5. API (все — владелец-скоуп, схемы Pydantic v2)
`GET/POST /api/projects/{id}/payment-stages`, `PATCH/DELETE …/{stage_id}`, `POST …/{stage_id}/receive`; `GET/POST /api/projects/{id}/work-hours`, `PATCH/DELETE …/{entry_id}`; `GET /api/projects/{id}/margin`; профиль исполнителя принимает `hourly_rate`; платёж принимает `stage_id`.

## 6. Данные (миграция 0075, обратимая)
* `payment_stages` (id, owner_id, project_id CASCADE, position, title **зашифрован**, percent NULL, amount NULL — ровно одно из двух, due_on NULL, created/updated);
* `project_payments.stage_id` (FK SET NULL, CHECK: только аванс / оплата);
* `work_hours` (id, owner_id, project_id CASCADE, worked_on, hours, note **зашифрована**, created/updated);
* `executor_profiles.hourly_rate` (NULL; > 0).
Откат: удаляет таблицы и колонки; **отказывается, пока есть этапы или часы** (это ввод владельца, молча не стираем).

## Критерии PASS
1. Суммы этапов, статусы, сверка, маржа — только на сервере, покрыты тестами (граничные случаи: нет договорной суммы, нет ставки, нет часов, архивные записи, чужой владелец).
2. Привязка поступлений к этапам и «Otrzymano» за одно касание; удаление этапа не теряет деньги.
3. Миграция 0075 вверх / вниз / вверх на PG16; откат отказывает при данных.
4. Экран: 4 языка, 320 / 390 / 412, светлая / тёмная, нет горизонтальной прокрутки, цели ≥ 44 px.
5. Регрессия (4 шарда, vitest, tsc, build); скрипт выкладки с миграцией и пробный прогон.
