# V2-13 — пакеты профессий в профиле и фильтры по ним

Решения владельца (2026-11-02, после приёмки V2-12b): в профиле — галочки **шести пакетов**: **Отделка** (подготовка, гладь, штукатурка, малярка, welon, декоративные, откосы), **ГКЛ**, **Микроцемент (отдельно, перед Плиткой)**, **Плитка**, **Электрика**, **Сантехника**; у всех существующих пользователей (и у новых) **включено всё**; в прайсе выключенные профессии **скрываются, внизу «Показать все»**; кроме прайса фильтруются **работы в «Rodzaje prac i jakość»**, **материалы помещения** и **«Точки и трассы»**.

## Идея
Мастер, который делает только плитку, не хочет видеть категории электрика в прайсе, работы сантехника в плане стены и пакет ГКЛ в материалах помещения. Профессия называет, что ей принадлежит: **категории прайса** (а через них — работы, которые приходят из прайса, и категории точек и трасс) и **пакеты материалов** помещения. Остальное (универсальные «Punkty i trasy», «Materiał», «Inne») есть всегда.

**Ничего не удаляется и не блокируется.** Выключенная профессия только убирает предлагаемое для НОВОГО выбора; уже существующее (строка сметы, расчёт материалов, точка помещения) остаётся видимым. Фильтр — удобство, а не запрет.

## 1. Данные (миграция 0084, обратимая)
Одна новая колонка `users.trades` (JSON-список ключей, nullable). **NULL = «никогда не выбирал» = все профессии включены** — ни у кого ничего не пропадает после выкладки, данные не переписываются. Пустой список — тоже выбор (предлагается только универсальное). Откат просто убирает колонку (это выбор «что предлагать», а не свидетельство).

## 2. Правила и API
* `domain/rules/trades.py` (чистые): `TRADES` в порядке мастера — `FINISHING, DRYWALL, MICROCEMENT, TILE, ELECTRIC, PLUMBING`; у каждой — категории прайса и пакеты материалов; `ALWAYS_CATEGORIES = POINTS_ROUTES, MATERIAL, OTHER`. Тест следит, чтобы **каждая категория прайса принадлежала ровно одной профессии или была универсальной** (новая категория не может появиться «ничьей») и чтобы пакеты материалов совпадали с известными базе.
* `GET /api/trades` — каталог (что кому принадлежит), универсальные категории и включённые профессии; `PUT /api/trades {enabled: […]}` — известные профессии, дубли убираются, порядок канонический, неизвестная — `422 TRADES_INVALID` с причиной (`UNKNOWN_TRADE` / `WRONG_TYPE`), ничего не меняется.

## 3. Экран
* **Профиль исполнителя** («Konto» → профиль): блок **«Zawody (pakiety)»** — шесть крупных галочек (≥ 44 px), каждая сохраняется сразу; подсказка «ничего не удаляется, только скрывается из списков».
* **Прайс:** список и фильтр категорий скрывают категории выключенных профессий; внизу **«Pokaż wszystkie kategorie (N ukrytych)»** — переключатель на время просмотра. Позиции, уже стоящие в сметах, не исчезают из смет.
* **«Rodzaje prac i jakość»** (выбор работы в плане стены / пола / потолка и при осмотре): работы из выключенных профессий не предлагаются.
* **Материалы помещения:** кнопки пакетов (Плитка, ГКЛ, Электрика, Сантехника) — только включённых; уже созданные расчёты видны всегда.
* **«Punkty i trasy»:** категории выключенных профессий не предлагаются.
* Нет связи / каталог не загрузился — **не скрывается ничего** (безопасный вариант).

## Критерии PASS
1. Правила: канонический порядок, дубли, пустой выбор, неизвестное → причина; `NULL` = все; каждая категория прайса принадлежит ровно одной профессии или универсальна; пакеты материалов = известным базе.
2. API: без токена 401; новый владелец — все включены; выбор у владельца свой; пустой выбор сохраняется; неверный — 422 и без изменений.
3. Миграция 0084 вверх / вниз / вверх (SQLite и PG16).
4. Экран: галочки в профиле сохраняются; прайс скрывает и «Pokaż wszystkie»; план работ, материалы и точки следуют выбору; существующие данные не пропадают; 4 языка, 320 / 390 / 419, светлая / тёмная; регрессия (4 шарда, vitest, tsc, build); скрипт выкладки с миграцией 0084 + пробный прогон; README пошагово.
