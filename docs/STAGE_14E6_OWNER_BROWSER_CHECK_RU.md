# Stage 14E.6 — проверка интерфейса фото в браузере (для владельца)

Это пошаговая инструкция для вашей проверки перед приёмкой 14E.6. Всё выполняется **локально, без Docker**, на **отдельном dev-бакете R2** (решение D-DEV).
Production в этой проверке не участвует: загрузка фото на production остаётся выключенной до этапа 14E.7.

> **Секреты.** Ключи R2 и пароли никогда не отправляйте в чат и не коммитьте. Они лежат только в вашем локальном незакоммиченном файле `.env`
> (он в `.gitignore`).

**Что изменено по вашим замечаниям (первая проверка в браузере):**

1. **Фото добавляются только на поверхностях:** *Ściana 1…N*, **Podłoga** и **Sufit** (у пола и потолка появилась кнопка фото). На «Объекте», в карточках комнат и на экране комнаты добавить фото нельзя.
2. У строк **проёмов** кнопки фото больше нет — фото двери/окна делается в карточке его стены.
3. **Объект и комната — только просмотр и правка:** «Zdjęcia obiektu» показывает **все** фото объекта; карточка комнаты (на вкладке «Объект») и новая карточка **«Zdjęcia pomieszczenia»** на экране комнаты показывают **все фото комнаты**
   (её собственные, со стен/пола/потолка и проёмов) с путём `комната → поверхность → …`. Число на кнопке комнаты = всё фото этой комнаты, поэтому расхождения «на вкладке Объект 1, а внутри кухни пусто» больше нет.
4. Подпись фото теперь всегда содержит поверхность (`kuchnia → Ściana 1 → …`), потому что фото добавляется на поверхности. Старые фото, добавленные прямо к комнате/объекту, остаются видны и редактируемы (путь у них короче).
5. Для этого на backend добавлены `room_totals` в счётчики и фильтр списка `in_room_id` (без миграции).

Ранее в реальном браузере уже было найдено и исправлено: просмотрщик был сдвинут на 12 px вниз (теперь выводится поверх страницы); при 3 колонках плитка была ~85 px (теперь **2 колонки до 480 px**); при недоступном сервере очередь писала «неожиданная ошибка» вместо «нет соединения».

**Чего автоматика не может проверить** (это остаётся за вами и за этапом 14E.7 на реальном телефоне): настоящая камера и галерея в Telegram на iOS/Android, формат фото (JPEG или HEIC),
путь через Cloudflare на мобильной сети, поведение BackButton и тёмная тема внутри настоящего Telegram, фон/возврат приложения во время загрузки (список — в контракте, §12).

## 1. Один раз: dev-бакет R2 и ограниченный токен

1. Cloudflare Dashboard → **R2** → **Create bucket**. Имя, например, `plan-estimate-photos-dev`. Расположение — **EU** (как у production).
   Публичный доступ **не включайте** (бакет остаётся приватным).
2. R2 → **Manage API tokens** → **Create API token**: права **Object Read & Write**, область — **только этот dev-бакет** (Specify bucket), без прав на другие бакеты.
   Скопируйте *Access Key ID*, *Secret Access Key* и *endpoint* вида `https://<account_id>.eu.r2.cloudflarestorage.com` (для EU-бакета в нём есть `.eu.`).
3. Убедитесь, что это **не** production-бакет и **не** токен production. Production-ключи сюда не подставляйте.

## 2. Один раз: локальные настройки

В корневой незакоммиченный `.env` (рядом с остальными настройками разработки) добавьте:

```
MEDIA_STORAGE_BACKEND=s3
MEDIA_S3_ENDPOINT_URL=https://<account_id>.eu.r2.cloudflarestorage.com
MEDIA_S3_BUCKET=plan-estimate-photos-dev
MEDIA_S3_REGION=auto
MEDIA_S3_ACCESS_KEY_ID=<ключ dev-токена>
MEDIA_S3_SECRET_ACCESS_KEY=<секрет dev-токена>
PHOTO_UPLOADS_ENABLED=true
```

Проверьте, что в `.env` остаются `MOCK_TELEGRAM_AUTH=true` и `VITE_DEV_MOCK_AUTH=true` (вход без Telegram только для локальной разработки) и `VITE_API_URL=http://localhost:8000`.

Миграция `0033` (колонка источника фото) нужна вашей **локальной** базе:

```bash
cd backend && source .venv/bin/activate && alembic upgrade head
```

(Production-базу это не затрагивает: туда `0033` попадёт только в 14E.7 с вашего отдельного одобрения.)

### 3б. Вариант: запуск через Docker (вместо раздела 3)

В `CLAUDE.md` локальный Docker по умолчанию запрещён (для меня и для рутинной разработки). Этот вариант — осознанное исключение **только для вашей ручной проверки**; запускаете его вы, у себя.
Если хотите закрепить Docker как разрешённый способ локальных проверок, скажите — я поправлю формулировку в `CLAUDE.md`.

Нужен файл **`docker-compose.photos-dev.yml`** из корня репозитория (он добавлен в этот этап). Базовый `docker-compose.yml` передаёт backend только несколько переменных, поэтому настройки фото
из `.env` без этого файла в контейнер не попали бы. В файле **нет секретов**: значения подставляются из вашего `.env` (раздел 2 выполняется так же, как для нативного запуска).
Если в `.env` ничего про фото нет, файл оставляет хранилище «disabled», а загрузку выключенной — backend стартует как с одним базовым файлом.

```bash
# 1) сухая проверка файлов и подстановок (контейнеры не создаются; вывода нет, только код возврата)
docker compose -f docker-compose.yml -f docker-compose.photos-dev.yml config --quiet

# 2) сборка и запуск: PostgreSQL 16 + backend + frontend
docker compose -f docker-compose.yml -f docker-compose.photos-dev.yml up -d --build

# 3) убедиться, что backend поднялся и миграции (включая 0033) применились
docker compose -f docker-compose.yml -f docker-compose.photos-dev.yml logs backend | tail -n 30
curl -s http://localhost:8000/api/health
```

Затем откройте `http://localhost:5173` и идите по чек-листу (раздел 4); вход — mock-авторизация, как в `README`.

* **Не** выполняйте `docker compose ... config` без `--quiet` и не присылайте вывод в чат: он печатает значения из `.env`, включая секретный ключ.
* Миграции применяются сами при старте backend (`alembic upgrade head`) — в **новой** базе в Docker-томе `postgres_data`, она не связана с вашей нативной. Раздел 2 про `alembic upgrade head` вручную тогда не нужен.
* Изменили `.env` (например, сменили ключи) — пересоздайте backend: `docker compose -f docker-compose.yml -f docker-compose.photos-dev.yml up -d --force-recreate backend`.
* Правки в `frontend/` подхватываются без пересборки (папка примонтирована); изменения в `backend/` требуют `up -d --build`.
* Порт `5432` занят вашим локальным PostgreSQL → остановите его или задайте другой `POSTGRES_PORT` в `.env`.
* Остановка: `docker compose -f docker-compose.yml -f docker-compose.photos-dev.yml down` (база сохраняется). **`down -v` удалит базу** — используйте, только если хотите начать с чистого листа.
* Этот файл **только для локальной разработки** и только для dev-бакета; production использует `docker-compose.prod.yml` и собственные настройки — не подставляйте ему production-ключи.
