# Stage 14G — метки-точки на фото (POINT annotations): план

Статус: **план 2026-10-08, старт одобрен владельцем («14G — метки на фото»)**; решения Q1–Q5 приняты владельцем 2026-10-08, реализация идёт подэтапами. Архитектура утверждена ранее: `docs/STAGE_14_PHOTO_FIXATION_ARCHITECTURE.md` §6.4, §15.4, §16, §17, решения D14-9, D14-10, D14-11, D14-15. Не входят: прямоугольники, рисование от руки, стрелки, текстовые блоки (отдельное решение владельца в будущем).

## 1. Что уже есть и чего нет

- **Есть:** фото (`photo_assets`), вложения во все контексты (`photo_attachments`), просмотрщик `PhotoViewer` (подпись, категория, «в отчёт», архив), полноэкранный просмотр с зумом (`PhotoFullscreen` + `ZoomableImage`), список / счётчики, резервная копия.
- **Нет:** таблицы `photo_annotations` (миграции `0031`–`0034` её не создают — в `0031` сказано, что аннотаций там нет), модели, API, интерфейса. **Нужна миграция `0035`**, поэтому выкладка 14G будет с миграцией и бэкапом перед ней (процедура раздела 69b / 72 runbook).

## 2. Правила (из утверждённой архитектуры)

1. Метка принадлежит **вложению** (`attachment_id`), а не файлу: то же изображение, прикреплённое к двум местам, имеет разные наборы меток (D14-15).
2. Метка — только «где на фото»: `x`, `y` в долях 0…1, начало в левом верхнем углу **правильно повёрнутого изображения для показа**; независима от размера экрана, миниатюры и PDF (D14-11). Никаких `finding_id`, серьёзности, статуса, категории дефекта (D14-9, D14-10); дефект остаётся записью осмотра (`InspectionFinding`), фото к нему — контекст `FINDING`.
3. Поля: `id`, `attachment_id` (CASCADE), `kind = POINT`, `x`, `y` (`numeric(7,6)`, CHECK 0…1), необязательная короткая подпись `label` (≤ 40 символов, напр. «1» или «трещина у окна»), `position` (порядок показа), `created_at`, `updated_at` (UTC).
4. Метку можно **удалить физически** (это презентация, фото не затрагивается); архивирование вложения метки не удаляет, восстановление возвращает их вместе с фото.
5. Метки редактируются только на **не архивном** вложении READY своего проекта и владельца; чужое / выдуманное → 404 (как везде).
6. Добавление и правка меток не меняют `photo_assets` и вложение (кроме `updated_at` ответа не требуется).

## 3. Подэтапы

### 14G.1 — API + миграция `0035_photo_annotations` (backend)
- Модель `PhotoAnnotation`, схемы (`PhotoAnnotationRead/Create/Patch`), сервис `PhotoAnnotationService` (владелец → проект → вложение; лимит меток на фото; `position` назначается сервером, по умолчанию в конец), исключения с кодами (`PHOTO_ANNOTATION_NOT_FOUND`, `PHOTO_ANNOTATION_LIMIT_REACHED`, валидация координат и подписи → 422).
- Маршруты: `GET/POST /projects/{p}/photo-attachments/{id}/annotations`, `PATCH/DELETE …/annotations/{aid}` (тонкие, без бизнес-логики).
- Списки фото и детали вложения получают `annotation_count`; детали — полный список меток (для показа без второго запроса). Фильтры и счётчики не меняются.
- Миграция: создаётся только таблица + enum + CHECK + индекс `(attachment_id, position)`, обратимая. Резервная копия: таблица попадает в дамп БД автоматически; **головa миграций меняется → образы бэкапа нужно пересобрать** (правило цепочки бэкапа), это входит в 14G.3.
- Тесты: матрица форм, граничные 0 / 1 / 1.000001 / −0.1 / не число, длина подписи 40 / 41, лимит, порядок, чужой проект / владелец / архивное вложение, каскад при физическом удалении вложения (только тест), совместимость остальных маршрутов, миграция вверх / вниз / вверх на PostgreSQL-совместимой проверке, мутационная проверка.

### 14G.2 — интерфейс (frontend)
- `PointMarkerLayer`: рисует метки поверх изображения в долях (не пикселях) — совпадает на миниатюре, в просмотрщике и в полноэкранном режиме при зуме; метка — кружок с номером ≥ 24 px видимой части, **зона касания ≥ 44 px** (невидимая подложка).
- Режим «Метки» в `PhotoViewer` (за кнопкой в «Opcje фото», не на виду): касание по фото ставит метку; метку можно выбрать, ввести подпись (≤ 40, счётчик символов), удалить; режим одновременно с зумом не конфликтует (в полноэкранном режиме метки видны, ставить можно в обычном просмотре и в полноэкранном после касания «Метка»).
- Метки видны в просмотрщике и полноэкранном режиме всегда; в сетке миниатюр — значок «n меток» (только счёт). Недоступно для архивного вложения (только просмотр).
- Ошибки, PL / RU, мобильные правила (320 / 390 / 412 px, переносы, без горизонтальной прокрутки, тёмная / светлая тема Telegram).
- Тесты: vitest + мутации; реальный Chromium 320 / 390 / 412 px, PL / RU, касание и зум.

### 14G.3 — выкладка и проверка владельцем
- Runbook с миграцией (по образцу 14F.4): бэкап перед миграцией, оценка миграции владельцем, пересборка backend + frontend + образов бэкапа, проверка подписанной ссылки с чужого адреса, проверка на телефоне. **Вместе выкладывается отложенная 14H.4** (компактные кнопки фото) — отдельных шагов для неё не потребуется.

## 4. Решения владельца (приняты 2026-10-08)

| № | Вопрос | Решение |
|---|---|---|
| Q1 | Максимум меток на одно фото | **10** (лимит на сервере, код `PHOTO_ANNOTATION_LIMIT_REACHED`) |
| Q2 | Подпись метки | необязательная, ≤ 40 символов; **показывается всплывающим окном по нажатию на метку** (там же удаление) |
| Q3 | Где ставить метки | **везде, где можно добавлять фото** (поверхность, проём, осмотр / вопрос, находка, работа в Realizacja); на фото объекта и помещения (только просмотр / редактирование агрегата) — как и сами фото, по правилам просмотрщика; на архивных — только просмотр |
| Q4 | Метки в PDF | **нужны**; формат пока не определён: в 14G данные (`x`, `y`, `position`, `label`) отдаются API и готовы для 14I / Stage 15 |
| Q5 | Перемещение метки | **нет**; метку можно **удалить** и поставить заново |
| Push | Пуш коммитов ветки `stage-14` | владелец разрешил делать **без отдельного одобрения** (2026-10-08); выкладка на production по-прежнему только по явному «да» |

## 5. PASS
- 14G.1: новые и все старые backend-тесты проходят; миграция вверх / вниз; мутации ломают тесты; контексты и маршруты фото без изменений.
- 14G.2: vitest, `tsc`, `vite build`; Chromium 320–412 px PL / RU без переполнения, цели касания ≥ 44 px, метки совпадают с точкой касания при зуме.
- 14G.3: метки ставятся, подписываются, удаляются на телефоне, видны после перезапуска, не появляются на другом вложении того же изображения; резервная копия с новой таблицей проходит проверку.
