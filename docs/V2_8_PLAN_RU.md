# V2-8. Ссылка для клиента (план и критерии PASS)

Шаг V2 из `docs/POST_MVP_PLAN_RU.md` («Ссылка для клиента: публичная страница объекта по секретной ссылке, „Принимаю смету“, „Согласую допработы“, журнал согласий»). Старт — по «Принимаю, V2-8» владельца (2026-10-24). Миграция **0072**.

## 1. Решения владельца (2026-10-24)

| Вопрос | Решение |
| --- | --- |
| Что видит клиент | **Позиции с суммами**: помещения, работы, количество, цены и итог (нетто/НДС/брутто по настройке V2-6). Не показываются: прайс, заметки, фото осмотра, другие объекты и клиенты, внутренние коды |
| «Согласую допработы» | **Отдельное предложение**: мастер создаёт предложение (название, описание, сумма, на сколько дней сдвигает срок); клиент нажимает «Согласую» или «Отклоняю». Предложение не меняется после создания (изменить = отозвать и создать новое) |
| Срок ссылки | **30 дней**, кнопки «Продлить» (ещё 30 дней от сегодня) и «Отозвать». После принятия сметы страница остаётся открытой, но смета в ней только для чтения; допработы можно решать до конца срока ссылки |
| Как фиксируется согласие | **Имя + галочка + запись в журнале**: время, версия сметы и её хеш (SHA-256), сумма, текст согласия, имя, хеши IP и браузера. Без SMS и кодов |

## 2. Что я решил сам (можно отменить)

* **Ссылка = `https://<домен>/c#<токен>`.** Секрет лежит во фрагменте (после `#`): он не уходит на сервер, не попадает в журнал Caddy, в Referer и в предпросмотр мессенджера. Страница сама читает фрагмент и шлёт токен в заголовке `X-Client-Link`.
* **Токен**: 32 случайных байта (`secrets.token_urlsafe`), в базе только SHA-256 токена (как вы одобрили). Показать ссылку повторно нельзя — «Новая ссылка» отзывает прежнюю и выдаёт другую. Одна действующая ссылка на объект.
* **Принятие сметы переводит смету FINAL → ACCEPTED** (как подписание договора), поэтому изменить принятую смету нельзя: новая версия потребует нового принятия. Что принял клиент, видно в журнале по хешу.
* **Устаревшая страница не может принять изменённое**: клиент отправляет хеш сметы / предложения, который он видел; не совпал → 409 «смета изменилась, обновите страницу».
* **Язык страницы клиента**: мастер выбирает при создании ссылки (по умолчанию PL), клиент может переключить PL / RU / UK / EN; выбор клиента **не сохраняется** в памяти браузера (на телефоне мастера не перепишет его язык). Текст согласия отдаёт **сервер** (правило проекта: юридические формулировки не в React): польский текст — обязательный и именно он пишется в журнал, перевод показывается рядом.
* Журнал **только добавляется**: ни изменения, ни удаления из приложения нет (удаляется только вместе с объектом при его очистке).
* Зашифровано (ключ владельца, EN-2): имя подписанта, название и описание предложения. Тексты согласия не содержат персональных данных и лежат открыто.

## 3. Данные (миграция 0072, 3 НОВЫЕ таблицы, существующие не меняются)

* `client_links`: `id`, `owner_id`, `project_id`, `token_hash` (уникален), `language`, `created_at`, `expires_at`, `revoked_at`, `last_viewed_at`, `view_count`. Частичный уникальный индекс: одна неотозванная ссылка на объект.
* `client_proposals`: `id`, `owner_id`, `project_id`, `sequence`, `title`*, `description`*, `amount`, `currency`, `extra_days`, `status` (OPEN / ACCEPTED / DECLINED / WITHDRAWN), `content_hash`, `created_at`, `decided_at`.
* `client_consents` (журнал): `id`, `owner_id`, `project_id`, `link_id`, `kind` (ESTIMATE_ACCEPTED / PROPOSAL_ACCEPTED / PROPOSAL_DECLINED), `estimate_id`, `estimate_version`, `proposal_id`, `subject_hash`, `amount`, `currency`, `statement`, `statement_lang`, `signer_name`*, `ip_hash`, `agent_hash`, `created_at`. Уникально: одно принятие на смету, одно решение на предложение.
* Всё с `ON DELETE CASCADE` от объекта и владельца. Зашифрованных колонок станет 64 (было 61).

## 4. API

Публичное (без входа, 3 операции; токен в заголовке `X-Client-Link`):

* `GET /api/public/client` — страница: исполнитель (название, телефон, e-mail, город), объект (название, адрес), смета (последняя FINAL/ACCEPTED), предложения, принятие, тексты согласия, срок ссылки.
* `POST /api/public/client/estimate/accept` — `{estimate_id, version, hash, signer_name, agree}`.
* `POST /api/public/client/proposals/{id}/decide` — `{decision, hash, signer_name, agree}`.

Защита: неизвестный токен → одинаковый 404; просроченная / отозванная → 410 `LINK_INACTIVE`; лимит запросов (в памяти, без Redis) по IP и по ссылке; `Cache-Control: no-store`, `X-Robots-Tag: noindex`, `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`; ответ — только белый список полей (тест сверяет ключи); размеры полей ограничены схемой.

Для владельца (с входом):

* `GET|POST|DELETE /api/projects/{id}/client-link`, `POST …/client-link/extend`;
* `GET|POST /api/projects/{id}/client-proposals`, `POST …/client-proposals/{pid}/withdraw`;
* `GET /api/projects/{id}/client-journal`.

## 5. Экран

* **Владелец** (в объекте, блок «Ссылка для клиента»): создать / новая ссылка, копировать, отправить в Telegram, срок, «Продлить», «Отозвать», когда открывали последний раз; предложения (форма: название, описание, сумма, дни; отозвать); журнал согласий.
* **Клиент** (`/c`): шапка с исполнителем; смета по помещениям с суммами; итог; блок «Принимаю смету» (имя, галочка с текстом согласия, кнопка); предложения с кнопками «Согласую» / «Отклоняю»; состояния: загрузка, ссылка неактивна, ошибка, уже принято. Mobile-first 320–480 px, цели ≥ 44 px, без горизонтальной прокрутки, PL/RU/UK/EN.

## 6. Критерии PASS

1. Тесты бэкенда: правила (токен, хеш, лимиты), сервисы, API владельца и публичный (успех, просрочено, отозвано, чужой токен, устаревший хеш, повтор, чужой владелец, утечки полей, заголовки, лимит), журнал без путей изменения, миграция вверх/вниз/вверх на PG16.
2. Аудит API (все операции кроме открытых требуют вход) обновлён ровно на 3 публичные операции.
3. Фронт: тесты блока владельца и страницы клиента, паритет 4 языков, аудит тёмной темы, `tsc`, `vite build`.
4. Живая проверка в браузере (390 / 412 / 320 px, 4 языка, светлая / тёмная): создать ссылку, открыть в «чужом» контексте, принять смету, решить допработы, увидеть журнал.
5. Скрипт выкладки `docs/V2_8_DEPLOY_RU.sh` (по образцу V2-7a) прогнан на заглушках, включая негативные сценарии.
