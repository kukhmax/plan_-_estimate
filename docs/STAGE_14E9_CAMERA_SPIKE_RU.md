# Stage 14E.9 — пробный образец камеры внутри приложения (spike)

**Статус:** выложен, проверен на телефоне владельца 2026-10-07 (результат ниже); решение о настоящей камере — за владельцем.
**Зачем:** кнопка «Zrób zdjęcie» в Telegram на Android не открывает камеру (Telegram игнорирует `capture` и показывает галерею).
Нужно выяснить на вашем телефоне, может ли страница получить камеру сама (`getUserMedia`) и какое качество снимка это даёт.
Только после ответа решаем, делать ли настоящую кнопку камеры (отдельный подэтап).

**Что это:** временный диагностический экран. Ничего не загружается на сервер, не сохраняется и не меняет данные;
backend, БД и миграции не затрагиваются. После решения экран удаляется.

## Как открыть

Mini App → внизу **«Konto»** → кнопка **«Diagnostyka kamery»** (по-русски «Диагностика камеры»).

## Что нажимать (3 минуты)

1. **«Uruchom kamerę — maksymalna rozdzielczość»**. Telegram или Android может спросить разрешение на камеру: разрешите.
   Ожидается живое изображение с камеры на экране. Если камера не стартует, в отчёте будет строка `getUserMedia failed … <имя ошибки>`.
2. Нажмите **«Zdjęcie: takePhoto»**, затем **«Zdjęcie: klatka z podglądu»**. Под превью появятся два снимка (#1 и #2).
3. По желанию: **«Zatrzymaj kamerę»**, затем **«Uruchom kamerę — 1920×1080»** и снова оба снимка (сравнить качество).
4. Прокрутите вниз до блока **«Raport do wysłania»** и пришлите мне его **скриншотом** (или кнопкой **«Skopiuj raport»**, если сработает копирование).

## Как я прочитаю отчёт

| Строка отчёта | Что она значит | Решение |
|---|---|---|
| `getUserMedia ok …` и `settings: 4000x3000` (или от 3264×2448) | камера доступна, высокое разрешение | настоящая кнопка камеры возможна, качество как у обычного фото |
| `settings: 1920x1080` | доступна, но только Full HD (~2 МП) | для фиксации дефектов обычно достаточно; решение за вами |
| `getUserMedia failed … NotAllowedError` | Telegram не разрешил камеру | проверьте разрешение камеры для Telegram в настройках Android и повторите; если не помогает, настоящая кнопка камеры невозможна, остаёмся на текущем варианте |
| `getUserMedia failed … NotFoundError / NotReadableError` | камера не найдена или занята | повторить после закрытия других приложений с камерой |
| `takePhoto ok … image/jpeg … 4000x3000` | полноразмерный снимок | лучший вариант съёмки |
| `takePhoto failed …` и `canvas ok …` | полный снимок недоступен, но кадр с видео работает | качество = размер видеопотока |
| `exif=none` у обоих снимков | у снимка нет даты съёмки | дата в подписи будет временем загрузки (нужно решить отдельно: брать время с устройства) |
| `track ended (the host stopped the camera)` | Telegram остановил камеру (например, при сворачивании) | при реализации нужен перезапуск потока |

## Откат и очистка

Экран только добавляет кнопку в «Konto»; откат — образ `:pre-…` frontend (теги на VM) или удаление подэтапа в следующем коммите.
Камера отключается при закрытии экрана и при выходе из приложения.

## Результат на телефоне владельца (2026-10-07)

Xiaomi 23122PCD1G, Android 16, Telegram-Android 12.10.6, Mini App API 9.6, WebView Chrome 153.

| Проверка | Результат |
|---|---|
| Камера доступна из Mini App | **да**, после запроса разрешения (`permission camera=prompt` → разрешено); старт 5 с вместе с нажатием «разрешить» |
| Камеры | 2 видеовхода, `facing=environment` получена |
| Поток при запросе 4096×3072 | `3072x3472`; возможности до 4624×3472 (16 МП, 4:3) |
| `takePhoto` | 1,2 с, **JPEG 4,92 МБ, 3472×3472 (квадрат, 12 МП), с EXIF (дата съёмки)** |
| Кадр с видео (canvas) | **14 с**, 2,04 МБ, 3072×3472, **без EXIF** — как основной способ непригоден |
| Фонарик | доступен (`torch=true`); зума нет |

Вывод: настоящая кнопка камеры возможна с хорошим качеством. Квадрат получился из-за запроса 4096×3072 (хост выбрал режим 1:1):
в реализации нужно явно запрашивать максимум сенсора (4624×3472) по `getCapabilities` / `getPhotoCapabilities`.

## Дополнение (14E.10): тест размеров снимков и зума

После проверки 14E.10 на телефоне: снимок всё равно квадратный (3472×3472), пинч-зума нет. Чтобы понять причину, в тот же экран добавлена кнопка **«Test rozmiarów zdjęć i zoomu»** (активна, когда камера запущена).

Как запустить: «Konto» → «Diagnostyka kamery» → «Uruchom kamerę — maksymalna rozdzielczość» → **«Test rozmiarów zdjęć i zoomu»** → дождаться окончания (камера выключится сама; ~10–20 с) → прислать отчёт скриншотом или кнопкой «Skopiuj raport».

Что делает тест (ничего не загружает и не сохраняет):

| Блок отчёта | Что проверяется |
|---|---|
| `== size ladder (takePhoto) ==` | `photoCapabilities` (диапазоны imageWidth/imageHeight), затем снимок по умолчанию и снимки с явным размером 4624×3472, 4000×3000, 3264×2448, 2560×1920, 1920×1440; строка `ask <размер> -> got <WxH> <МБ> in <мс>` или `failed` |
| `== zoom ==` | отдельный поток с запросом `zoom: true`: есть ли `capabilities.zoom` и принимает ли камера `applyConstraints` с зумом ×2 |
| `== exact-size stream ==` | поток с точным размером 4624×3472 и снимок по умолчанию: даёт ли такой поток 4:3 |

Как читать:

| Результат | Решение |
|---|---|
| какой-то `ask …` даёт 4:3 (например 4000×3000) | в 14E.10 запрашиваем этот размер (лестница размеров) |
| все `ask …` дают квадрат, а `exact stream` даёт 4:3 | снимок берётся из потока: открываем поток с точным 4:3 |
| везде квадрат | снимок 4:3 только из кадра потока (медленнее) или обрезка до 4:3 на нашей стороне; решение за владельцем |
| `capabilities.zoom` есть и `applyConstraints 2 ok` | пинч-зум через zoom трека |
| зума нет | цифровой зум (масштаб превью + обрезка снимка) |
