# Выкладка «Faktury i zaliczki» (IA-1…IA-6) — runbook

Статус: **подготовлено 2026-10-18, на production не применялось.** Скрипт: `docs/INVOICES_ADVANCES_DEPLOY_RU.sh` (проверен на заглушках `docker` / `curl` поверх настоящего git: 1 полный проход и 19 отказов — каждый останавливается на нужном шаге, до ворот M код на VM возвращается на прежнюю ветку). Ветка: `backlog-finance-encryption`. План и решения владельца: `docs/INVOICES_ADVANCES_PLAN_RU.md` (v2). Это пункт backlog, не этап дорожной карты.

## 1. Что выкладывается

| Часть | Что видит владелец |
|---|---|
| **IA-1/IA-2** расчёты по объекту | на объекте седьмая плитка «💰 Faktury i zaliczki»: сводка (договорная сумма, выставлено, оплачено, остаток, расходы, результат), три вкладки — «Faktury», «Od klienta» (авансы и платежи, можно привязать к счёту), «Materiały» (расходы); архив и восстановление записей (стереть нельзя). Это **реестр для себя, не бухгалтерия** и не выставление счетов (KSeF и VAT не затрагиваются) |
| **IA-3** фото чеков и счетов | у записи кнопка с камерой; фото идут тем же конвейером, что остальные, и видны в архиве фото с названием записи |
| **IA-4** без связи | записи можно создавать и менять в режиме полёта («Czeka na wysłanie»), суммы после синхронизации считает сервер; договорная сумма меняется только со связью |
| **IA-5** срок оплаты | у счёта с датой срока в календаре появляется «Termin zapłaty faktury: …»; **по умолчанию отправляется сообщение в Telegram за 3 дня и в день срока** (в утреннем дайджесте, не в тихие часы); отключается в настройках календаря. Оплаченный в полном объёме и архивный счёт напоминаний не создаёт |
| **IA-6a** PDF «Rozliczenie» | в документах объекта пункт «Rozliczenie» и кнопка «Rozliczenie dla klienta (PDF)» на экране расчётов: рабочая версия (водяной знак, без номера) и нумерованная ROZL/… (запись в журнале «Wysłane dokumenty»). **Расходы в документ не попадают.** Это справка, не счёт и не бухгалтерский документ |
| **IA-6b** категории расходов | в форме расхода пять кнопок «Na co wydano» (по умолчанию «Materiały»), на карточке — категория, в сводке — части расходов по категориям; расходы, сделанные до обновления, остаются «Bez kategorii» |

**Чего выкладка НЕ делает:** ничего не удаляет и не меняет в существующих данных (миграции только добавляют). Цикл сообщений календаря не трогается (скрипт сверяет его состояние до и после). Зависимости, образы, compose, Caddy, секреты — не меняются (скрипт отказывается, если они изменились).

## 2. Порядок (владелец; каждый шаг — новая SSH-сессия на VM, если не сказано иное)

1. **Проверьте, что VM чистая:** `cd ~/apps/plan_-_estimate && git branch --show-current && git status --short` (ожидается ветка, на которой вы выкладывали архивную чистку, и пустой вывод `status`).
2. **Свежий бэкап A9 перед миграциями** (скрипт выкладки откажется работать без копии моложе 72 часов). База сейчас на `0057_purge_ledger`, код — из `main`:
   ```
   cd ~/apps/plan_-_estimate && git fetch -q origin main && git show origin/main:docs/STAGE_18_BACKUP_A9_RU.sh > ~/backup_a9.sh && BACKUP_BRANCH=main BACKUP_HEAD=0057_purge_ledger bash ~/backup_a9.sh
   ```
   Ожидается `A9 PASS`. После этого **закройте эту SSH-сессию** (в оболочке остаются переменные бэкапа).
3. **Выкладка** (новая сессия; скрипт сам берёт файл из origin, VM не меняется до проверок):
   ```
   cd ~/apps/plan_-_estimate && git fetch -q origin backlog-finance-encryption && git show origin/backlog-finance-encryption:docs/INVOICES_ADVANCES_DEPLOY_RU.sh > ~/deploy_ia.sh && bash ~/deploy_ia.sh
   ```
   Ход: G0 проверки (только чтение) → G1 сборка (старый production работает) → **ворота M: фраза `МИГРАЦИИ 0058 0059 0060 0061 ДА`** → G2 backend и миграции → G3 frontend → G4 кнопка Telegram с новым `?v=`. Любой отказ останавливает всё и печатает порядок отката. Присылайте весь вывод.
4. **Телефон** (раздел 5).
5. **Бэкап под новую голову** (без него следующий бэкап при голове `0061` откажется работать): новая сессия,
   ```
   cd ~/apps/plan_-_estimate && BACKUP_BRANCH=backlog-finance-encryption BACKUP_HEAD=0061_expense_category bash ~/backup_a9.sh
   ```
   (скрипт `~/backup_a9.sh` уже лежит с шага 2). Потом закройте сессию.
6. **Приёмка и слияние в `main`:** «принимаем» — моя запись в журнале; слияние `backlog-finance-encryption` → `main` и переключение VM на `main` — только по вашему отдельному «да».

## 3. Миграции, простой, оценка

| Миграция | Что делает | Влияние |
|---|---|---|
| `0058_project_payments` | две новые **пустые** таблицы: `project_payments` (счета, авансы, платежи, расходы) и `project_finance` (договорная сумма), внешние ключи на пользователя и объект (`ON DELETE CASCADE`, записи уходят вместе с объектом) | ничего существующего не затрагивает |
| `0059_payment_photos` | в `photo_attachments` пустая колонка `payment_id` (внешний ключ `RESTRICT`), проверка «к чему привязано фото» расширена словом `PAYMENT`, уникальный индекс «одно активное фото записи на файл» | существующие привязки не меняются |
| `0060_settlement_document` | проверка видов документов журнала расширена словом `SETTLEMENT` | строки не меняются |
| `0061_expense_category` | в `project_payments` пустая колонка `category` и две проверки | ничего существующего не затрагивает |

Проверено на настоящем PostgreSQL 16: вверх, вниз, вверх; неизвестные значения отвергаются проверками; откат отказывается, пока записаны данные. Время — миллисекунды; простой API около 30–60 секунд (пересоздание backend). Бэкап A9 до — обязательное условие скрипта. Скрипт после миграций сверяет: версия `0061`, две таблицы, колонки, три проверки, **таблицы расчётов пусты**, число клиентов / объектов / документов / фото то же.

## 4. Откат — ПОРЯДОК ВАЖЕН

Старый образ backend **не запустится** на базе с применёнными миграциями (входной скрипт делает `alembic upgrade head`, а старый код не знает версию `0061`). Поэтому откат образа без отката миграций не работает. Рабочий порядок (скрипт печатает его при любом отказе после ворот M):

1. сначала откатить миграции **новым** кодом: `docker compose --env-file .env.production -p plan-estimate -f docker-compose.prod.yml run --rm --no-deps --entrypoint alembic backend downgrade 0057_purge_ledger`;
2. вернуть оба образа: `docker tag plan-estimate-backend:pre-ia plan-estimate-backend:latest && docker tag plan-estimate-frontend:pre-ia plan-estimate-frontend:latest`;
3. `docker compose --env-file .env.production -p plan-estimate -f docker-compose.prod.yml up -d --no-deps --no-build backend frontend`.

**Граница отката:** миграции откатываются без потерь, **пока вы не ввели ни одной записи расчётов**: откат `0058` отказывается, если в `project_payments` или `project_finance` есть строки; `0059` — если есть фото записи; `0060` — если выдан документ «Rozliczenie»; `0061` — если у расхода записана категория. После первой записи назад пути нет, только вперёд новым выпуском (ничего не теряется, откат просто отказывается). Новый frontend со старым backend не работает (новые маршруты), поэтому откатываются оба образа сразу.

## 5. Чек-лист на телефоне (полностью закройте Telegram, откройте Mini App по кнопке меню)

Проверяйте на **390 и 412** (если есть возможность), на польском и русском. Нужен объект с клиентом и профилем исполнителя (для PDF).

1. **Плитка и пустой экран.** На объекте седьмая плитка «💰 Faktury i zaliczki» → экран: заметка «Rejestr pomocniczy… nie jest fakturą», все суммы «0,00 zł», вкладки «Faktury / Od klienta / Materiały». Нет горизонтальной прокрутки.
2. **Договорная сумма.** «Ustaw umówioną kwotę» → ввод с запятой («12000,50») → «Zapisz». Если у объекта есть принятая смета — кнопка-подсказка «Z kosztorysu…», подставляется только по нажатию.
3. **Счёт.** «Dodaj fakturę»: название (или подсказка), сумма, дата, **срок через 3 дня**; под полем срока — пояснение про напоминание календаря. Сохранить → карточка со статусом «Do zapłaty».
4. **Аванс и платёж.** Вкладка «Od klienta» → аванс; «Opcje» → привязать к счёту → счёт «Częściowo», в сводке «Otrzymano» и «Do otrzymania» изменились; платёж на остаток → счёт «Opłacona». Суммы в сводке считает сервер: сверьте с калькулятором.
5. **Расход и категория.** Вкладка «Materiały» → «Dodaj wydatek»: магазин, сумма, «Paragon / Faktura»; в «Na co wydano» выбрано «Materiały» — нажмите «Narzędzia»; сохранить. На карточке видна категория; в сводке под «Wydatki na materiały» строки по категориям (старых расходов нет — «Bez kategorii» не появится, пока не было расходов без категории).
6. **Фото записи.** У расхода кнопка камеры → фото чека → счётчик на кнопке; в архиве фото снимок есть, место называет запись («Faktury i zaliczki › название»).
7. **Календарь.** В календаре на день срока счёта — «Termin zapłaty faktury: …»; в настройках календаря новый вид напоминаний можно выключить. Оплаченный счёт из календаря исчезает.
8. **«Rozliczenie» для клиента.** Кнопка «Rozliczenie dla klienta (PDF)» на экране расчётов → экран документа: «Wersja robocza» → в чат с ботом приходит PDF с водяным знаком; в нём счета, авансы/платежи, итоги; **расходов нет**. «Wyślij rozliczenie (PDF)» → PDF с номером ROZL/… и строка в «Wysłane dokumenty». Кнопка «назад» возвращает в список документов. На новом объекте без счетов и платежей нумерованная версия отказывает понятным сообщением, рабочая — приходит.
9. **Архив.** Архивируйте счёт → он исчезает из списка и сводки, не попадает в PDF; «Pokaż zarchiwizowane» → «Przywróć».
10. **Без связи.** Режим полёта → добавьте расход и счёт: «⏳ Czeka na wysłanie», примечание «суммы без ожидающих записей»; «Zmień umówioną kwotę» недоступна с пояснением. Верните связь → записи уходят сами, без дублей, суммы обновляются.
11. **Вёрстка.** Длинные названия переносятся, кнопки ≥ 44 px, ничего не наезжает друг на друга (особенно русские подписи: «Расчёт с клиентом (PDF)», «На что потрачено»).

Что считать провалом: суммы в сводке не сходятся с записями; расход виден в PDF «Rozliczenie»; дубли записей после возвращения связи; нумерованный PDF без профиля исполнителя; горизонтальная прокрутка; напоминание календаря у оплаченного или архивного счёта.

## 6. Что важно знать

- **Рассылка по сроку счёта включена по умолчанию** (решение разработчика, переключается в настройках календаря). Пока счетов со сроком нет, сообщений нет. Просроченный счёт в календаре виден, отдельного «опоздавшего» сообщения для него не делается (правило Stage 18C).
- **Деньги** — только десятичные числа; суммы и состояния счетов считает сервер, телефон лишь показывает. Результат = получено минус расходы (кассовый результат, не прибыль в бухгалтерском смысле).
- **Расходы не попадают ни в какой документ клиента** — это ваши собственные затраты.
- Записи не стираются: только архив и восстановление; вместе с объектом записи удаляются (как всё остальное в объекте), окно удаления объекта называет число записей расчётов, которые уйдут вместе с ним.
- Образы бэкапа пересобирает следующий запуск A9 (шаг 5 раздела 2); инструмент бэкапа не менялся.
