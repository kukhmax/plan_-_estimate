# V2-12b — протокол опрессовки (próba ciśnieniowa)

Решения владельца (2026-11-01, после приёмки V2-12a): **список у объекта, одна запись = одно испытание** (как «Roboty zanikające»); поля — **система** (холодная вода, горячая вода, отопление, газ, канализация) **+ участок / помещение текстом**, **среда** (вода или сжатый воздух), **давление испытания, бар**, **время выдержки, мин**, **падение давления, бар**, **дата и время**, **замечания**, **до 4 фото манометра** из фото объекта; **присутствующие** — из лиц объекта, а если заказчик не пришёл — **дата уведомления**; **строки подписи** исполнителя и заказчика; **пронумерованный (замороженный) выдаваемый протокол и рабочая версия с водяным знаком**; документ — на польском.

## Идея
Протокол ведётся как «Roboty zanikające» (16G): черновик → выдан (заморожен, PDF + запись в журнале отправленных) → архив. Приложение **ничего не оценивает**: допустимое падение давления зависит от системы и норм, поэтому результат («pozytywny» / «negatywny») — слово мастера; числа печатаются как введены. Это правило (детерминизм, никакого ИИ) то же, что везде.

## 1. Данные (миграция 0082, обратимая)
Таблица `pressure_test_protocols`: `owner_id`, `project_id` (CASCADE), `sequence` (номер у объекта), `status` (DRAFT / ISSUED / ARCHIVED), `held_on`, `held_time`, `customer_absent`, `notified_on`, `attendees` (зашифровано), `system`, `section` (зашифровано), `medium`, `test_pressure_bar` и `pressure_drop_bar` (`numeric(6,2)`), `duration_min`, `photo_ids`, `result`, `remarks` (зашифровано), `issued_at`, `snapshot` и `document_html` (зашифровано). CHECK на перечисления и диапазоны; уникальность `(project_id, sequence)`; **один черновик на объект** (частичный уникальный индекс). Та же миграция расширяет проверку вида в журнале (`PRESSURE_TEST_PROTOCOL`, префикс номера `PPC`). Откат **отказывает**, пока есть протокол или строка журнала.

## 2. Правила (`domain/protocols/pressure.py`, чистые)
* Давления: число с не более чем двумя знаками, 0 < давление ≤ 100 бар; падение — 0 ≤ падение ≤ 100 (ноль — «без падения»). Время выдержки — целое 1…1440 мин. Запятая принимается.
* Фото: до **4**, только активные фото этого объекта (объекта, помещения или поверхности).
* Присутствующие — лица объекта (не в архиве) и/или «другое лицо» (имя, функция).
* Условия выдачи (пустой список = можно выдавать): профиль исполнителя, клиент объекта, система, среда, давление, время, падение, дата, (дата уведомления, если заказчик не пришёл, иначе присутствующие), хотя бы одно фото манометра, результат, замечания (обязательны при «negatywny»). Договор **не нужен**: опрессовку делают и до договора.

## 3. Экран («Umowa i protokoły» → «Protokoły» → «Protokół próby ciśnieniowej»)
Начать / продолжить / новый протокол; форма: система (кружки), участок, среда, три числа (десятичная клавиатура), дата и время (по умолчанию «сейчас»), фото манометра (галочки, при четырёх остальные неактивны), «заказчик не пришёл» → дата уведомления вместо присутствующих, результат (две крупные кнопки), замечания; блок «Gotowość protokołu» с причинами; рабочая версия, «Wystaw protokół», «Odrzuć szkic» (с подтверждением). Каждое нажатие сохраняется сразу (очередь запросов). 4 языка, цели ≥ 44 px, одна колонка.

## 4. PDF
`Protokół próby ciśnieniowej`: объект, система и участок, среда, таблица «ciśnienie próbne / czas utrzymania / spadek», дата и время, присутствующие (или «zawiadomiony dnia …»), фото манометра с подписью и временем, результат, замечания, строки подписи исполнителя и заказчика. Две формы: рабочая (водяной знак, без номера, пустые поля вместо недостающего, не отказывает) и пронумерованная `PPC/…` (замороженный снимок, повторная выдача читает снимок, а не живые данные).

## Критерии PASS
1. Правила: диапазоны, запятая, ≤ 4 фото, чужой владелец — 404, неизвестное фото / лицо — понятная причина; условия выдачи по порядку; рабочая форма не отказывает.
2. Жизненный цикл: один черновик, выдача замораживает, изменение выданного — отказ `PRESSURE_NOT_EDITABLE`, следующий протокол получает следующий номер.
3. PDF: обе формы, настоящий PDF, фото манометра, подписи, одностороннее уведомление.
4. Миграция 0082 вверх / вниз / вверх на PG16; откат отказывает при данных.
5. Экран: 4 языка, 320 / 390 / 419, светлая / тёмная, нет горизонтальной прокрутки; регрессия (4 шарда, vitest, tsc, build); скрипт выкладки с одной миграцией + пробный прогон; README пошагово.
